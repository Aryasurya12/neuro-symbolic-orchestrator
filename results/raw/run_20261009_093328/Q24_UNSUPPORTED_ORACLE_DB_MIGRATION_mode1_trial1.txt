### Why this configuration
* **Oracle DB** runs comfortably on a t3.large (2 vCPU, 8 GB) for a typical OLTP workload; it leaves headroom for OS and Oracle processes.
* **Multi‑region DR** uses two AWS regions (us‑east‑1 primary, us‑west‑2 secondary). The combined SLA is:  
  `1 - ((1‑0.9995)*(1‑0.9995)) = 99.99975 %` – well‑above typical enterprise requirements.
* **Dynamic scaling** (bandwidth = 300 Mbps, 4 workers) gives a CPU utilisation of:  
  `CPU % = (300 Mbps / (4 × 75 Mbps)) × 100 % = 100 %` – the workers are sized to keep each at ~100 % peak, which is acceptable for a burst‑oriented front‑end. Adjust replicas up/down as actual load varies.
* All resources stay within the catalog limits (≤ 730 h/month per SKU, ≤ 16 replicas, bandwidth ≤ 1000 Mbps).

### Rough migration timeline
| Phase | Activities | Approx. Duration |
|-------|------------|------------------|
| **1. Planning & Design** | Requirements capture, network/VPC design, DR topology, IAM roles | 1 week |
| **2. Environment Setup** | Provision VPCs, subnets, security groups, IAM, create the two t3.large instances, configure replication (Oracle Data Guard) | 1 week |
| **3. Data Transfer** | Use Oracle RMAN over VPN/Direct Connect or AWS Snowball for large datasets. Typical on‑prem → AWS transfer ≈ 5 TB / 100 Mbps ≈ 11 days; Snowball can cut this to 2‑3 days. | 1‑2 weeks |
| **4. Cut‑over & Validation** | Switch application traffic to primary DB, run functional & performance tests, verify DR fail‑over | 3‑5 days |
| **5. Optimization & Handover** | Tune instance sizes, set up monitoring/alerts, hand over to ops | 3‑4 days |

**Total estimated effort:** **3 – 4 weeks** (≈ 20‑30 working days), assuming network bandwidth of ~100 Mbps and no major data‑size surprises. Using AWS Snowball can shrink the data‑transfer window to ~1 week, bringing the overall project to **≈ 2 weeks**.

---

**Bottom line:** Deploy a primary t3.large in **us‑east‑1** with a DR replica in **us‑west‑2**, connect them via the calculated DR link, and add a scalable front‑end (300 Mbps, 4 workers). The solution costs **≈ $572 per month** and can be migrated in **2‑4 weeks** depending on data‑transfer method.
